## Method fixed before data arrays
Convert full descriptors to FP64, require finite norms >1e-12, normalize each row, and compute full cosine C. Invalid inputs make the pilot invalid, not a removable hard pair. For each historical native edge(i,j), define m=min(Cij-max(k!=j)Cik, Cij-max(l!=i)Clj). Select min(32,N) anchors with smallest m; deterministic ties use original source ID then target ID. Do not repair possible FP32/FP64 tie differences.

Source pool S is the sorted union of anchor source IDs and the highest-cosine competing source l!=i for each anchor target (ties: lowest source ID), hence |S|<=64. Target pool T is the sorted union of each S row's four highest-cosine targets (ties: lowest target ID) AND all anchor target IDs, hence |T|<=288. Use the COMPLETE dense SxT cosine graph, not only its top4 edges. This persistence is conditional on the truncated graph and freely assignable pooled rows, not a full2048 assignment guarantee.

Give each source one private zero-score unmatched column; other sources cannot borrow it. Maximize total cosine using SciPy's pinned FP64 assignment with rows/columns in declared order, no jitter. For an anchor present in one optimum M*, compute delta=V*-V_without_edge, blocking that edge and resolving. An anchor absent from M* has delta=0. At most33 solves per filter evaluation. Exactly six evaluations per pair (one warmup plus five timed) give at most1584 assignment solves across the eight-pair pilot; warmup outputs supply the primary masks, with no extra untimed evaluation. Compute objective sums using math.fsum. Values in [-1e-10,0) clamp to0; a lower delta invalidates the numerical result. Remove the anchor unless delta >0.05+1e-10; the tolerance band is conservatively rejected. Epsilon0.05 is an objective margin, not calibrated uncertainty. No post-result threshold, pool or tie tuning.

AR emits ONLY a subset of saved fast coordinates: delete those selected anchor edges; retain every other native match unchanged in original order. It cannot improve correspondence recall by adding true matches. The question is downstream pose utility; physical correspondence correctness is UNKNOWN on this P8 data.

## Six arms and strong controls
Ordered arms: stock, fast, ar, cosine, margin, spatial_margin.
- stock/fast use the complete respective saved coordinates, followed by fresh pose calls.
- ar uses the fixed filter above on fast coordinates.
- cosine removes exactly q anchors of lowest Cij from the SAME anchor set, where q is AR's label-free per-pair removal count.
- margin removes exactly q anchors of lowest m from the same set.
- spatial_margin removes exactly AR's number of anchors in EACH4x4 source-image bin, choosing lowest m within that bin. Bins use unrefined raw_p0 source keypoints in the PROCESSED raster (not original RGB coordinates) and its processed image dimensions: floor(4*x/width),floor(4*y/height), bounded0..3. This matches removal coverage; all outside anchors remain untouched.
